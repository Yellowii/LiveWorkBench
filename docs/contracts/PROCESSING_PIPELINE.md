# Processing Pipeline v1（内部增量接口）

2026-10-13。保留CORE_CONTRACTS与PUBLIC_API 0.1已有路由/字段，本页定义当前授权的分层实现，不新增网络服务。RawRecorder.append → RawCommit 后才能ACK；TransportUnpacker.unpack(rawCommit) → transport结果与ProtoRef；OfficialParser接独立业务payload；ParserExtensions独立增强；随后去重/事件总线/存储。

TransportUnpacker从已落盘RAW读取并校验SHA256，不解释业务、不去重。Node复用官方传输类型/wire校验；C#复用protobuf-net/GZip，并对照其输出。差异留证据，不让IPC输出替代RAW。解包失败有稳定阶段/错误码，父RAW保留。HTTP生命周期JSON独立留证据，不能替代Proto。

ProtoIndex关联recordingId/rawId/messageIndex/method/msgId/payloadHash/size/parseStatus/eventId。压缩数据rawOffset=null，采用逻辑消息索引。派生payload在本数据域独立fsync文件；已有历史业务payload只引用原只读文件，不复制用户样本。payload路径只供后端内部使用。重复输入逐条留RAW/ProtoRef，重复事件可链接已有eventId。

第一增量仅给现有GET recording RAW详情新增processing传输/消息元数据；GUI原详情经正式接口展示。旧库CREATE TABLE IF NOT EXISTS加入索引，不重写既有RAW/事件/文件。新增解析/重新解析REST在对应增量同步PUBLIC_API。未知/失败类型保留payload引用，自定义增强不修改native。Replay后续拆出物理隔离仓库；当前namespace隔离不冒充数据库隔离。

RAW边界是代理HTTP响应主体、重组WS二进制消息或历史业务payload，不是TCP/TLS原包。应用控制PushFrame有RAW/control记录；WS Ping/Pong单独统计，不当业务Proto。无法保存必须留缺口，不把异常全文、原始字节或凭据返回API。

第二增量：OfficialParser.parseBusiness(ProtoRef, bytes)输出独立status/errorCode/parserVersion/native data，decode兼容适配仍供旧历史回归调用；正式管线不用混合decodePacket。ParserExtensions v1只生成独立extensions/occurredAt。ProtoIndex追加parse attempts，保存origin/namespace/input payloadHash/native结果；手动重新解析不发布业务事件，Replay不能覆盖原live Proto的eventId。

WebSource raw-first-v3增加packetDecoder注入，ACK编码复用固定官方传输契约并与业务解析分开；业务decode实际只执行一次。固定上游live.js仍原SHA256，生成v3 SHA256 e4c89b056af1b3bceb28bfc2dfa27fe7bdb497dab071273b7fc9918e929f4fbb。原v2与官方Parser不覆盖；生成资产保持本地忽略。心跳/重试仍由原LiveClient维持。

第三增量：RawRecorder正式独立文件，默认最多64个待持久化输入；8MiB以上拒绝且记录缺口，空二进制保存零字节RAW再报解包空输入。fsync/SQLite失败或背压无成功ACK。失败记录SQLite FULL，回退private capture-failures.jsonl fsync；磁盘/DB都不可用时只能本地stderr告警/unavailable，不宣称输入已保存。崩溃后孤立RAW索引恢复与回退journal跨重启查询仍待后续实现。

C#完整接收消息带连接ID/输入序号；WS控制帧透明转发并统计，不当业务Proto。FIN前超过上限、被新Binary打断、Close/仅本代理连接的TCP结束或代理停止，都记录不完整/拒绝缺口，不把残片伪造成完整RAW。TCP观察只关联自有代理接受的端点，不判断平台下播；连接观测失败也留诊断。已落盘但C#传输阶段中断的RAW用同一Node解包组件补处理。没有创建上游心跳/ACK。

WebSource v4继续原心跳/ACK/有限重连；仅allowLocalTest支持缩短重试以验证，生产延迟不变。生成SHA256 d952d9992dabe5d215ecedbd2e0cb26b04bd26d88aa768e1d170ff65e1d84903。GatewaySocketHub独立维持前端Ping/Pong和超时清理，控制帧统计与业务RAW分开。中断scope=unknown-range表示不确定范围，不等于已证实丢了N条或零丢包。

第四增量：Runtime为兼容入口/场次协调，正式职责拆到ProcessingPipeline、RawRecorder、TransportUnpacker、OfficialParser/ParserExtensions、MessageDeduplicator、EventBus、EventStore、HistoryQuery、ReplayEngine、LogService、MetricsService与GatewaySocketHub。去重保持既有namespace/room/method/msgId规则；总线主提交先通过正式EventStore持久化，再发events.appended，故障消费者独立记录，不阻断其他消费者。并未重写底层代理/官方协议资源。

ReplayEngine只创建本项目`dataDir/replays/{id}`独立Runtime/SQLite/Proto索引/总线；没有Capture/Source/网络/设备实例。父RAW只读引用，每步核对SHA256，派生payload在隔离目录。播放/暂停/单步/跳转重建沿用正式解包/解析组件。实时DB的RAW/事件/场次/日志/解析记录以及live总线不接收Replay写入；Gateway从Replay专用UI emitter读取经过投影的结果。

`history-view.sqlite`是独立查询读模型，保存实时/Replay查询投影与统一查询序号，保留现有降序签名快照分页/高水位语义；不把Replay行写入实时workbench.sqlite。真实仓库与查询序号区分，eventId和streamId不变。读模型重启可查询已保存的Replay事件；Replay控制job/打开的工作区仍是本进程状态，重启后需要新建回放，未实现控制job恢复。Raw/Proto查询可带namespace定位当前隔离工作区，重建结果使用独立上下文链接，不覆盖live关联。GUI也可分页检查无业务事件的RAW（控制/传输失败）。

RAW append入口先复制调用者字节，避免生产者重用Buffer后写入内容与原SHA256不一致。未实现完所有持久化调度/保留期/崩溃恢复；详见STATUS真实限制，不把模块分离等同完整P0。
